# Motion RPG — 경계의 숲

실행 주소: https://secom3-tech.github.io/motion-rpg/preview.html

**운동을 게임의 목표가 아니라 게임 조작으로 만드는 판타지 RPG.** 숲 입구의 마을을 거점으로 3D 몬스터를 사냥하고, 야외에서는 이어폰과 GPS 페이스로 원정을 진행한다. 같은 캐릭터가 성장한다.

## v0.28 통합 플레이

- 마을: 숲마을 전경과 사냥꾼 캐릭터, 길드 의뢰 게시판, 대장간, 숲길 안내인.
- 실내: WebGL 3D 몬스터 5종(슬라임 3종·그림자 늑대·유적 골렘), 반격 예고, 회피, 플레이어 기력, 장비 효과.
- 대장간: 실제 소유한 장비만 장착. 몬스터 사냥 XP·골드·제작 재료 → 제작 → 전투 능력치 상승. 고급 장비는 레벨/보스 격파 필요.
- 야외: 음성 중심 GPS 모험 및 러닝머신과 책상 시뮬레이션. 책상 모의 플레이와 수동 러닝머신 입력은 실제 보상을 지급하지 않는다.
- 장비 외형 시착은 실제 소유·제작·전투 능력치와 분리돼 있다.

## 조작

- 시점: 드래그 / 마우스.
- 이동: 왼쪽 가상 조이스틱 또는 WASD.
- 근거리 공격: 검격 버튼 또는 F.
- 원거리: 투척 버튼 또는 Space. 사냥활을 장착하면 사냥 화살로 표시된다.
- 회피: 회피 버튼 또는 Q/Shift. 경고 뒤 적절한 타이밍에 대응한다.
- 마을 복귀: 전투 정산. 재료를 받은 뒤 마을의 장비실에서 제작/장착한다.

## 현 단계에서 미완성

- 마을·캐릭터는 3D풍 캔버스 시안이다. 자유 이동형 진짜 3D 마을 및 실내 캐릭터 모델의 시각적 연동은 미구현.
- 폴드6 카메라의 관절 회피 인식, S21 실제 검격/투척 신호와 3D 전투의 실시간 연결은 미완성.
- GPS/이어폰과 백그라운드 탐험의 실제 기기 시험이 필요하다.
- 저장은 브라우저 localStorage만 사용한다. 계정/서버 저장 및 변조 방지가 없으며, 정식 다중 사용자 경제에 적합하지 않다.
- 테스트는 npm test로 실행한다. 자동 밸런스 검사는 실제 플레이의 재미나 운동 안전성을 입증하지 않는다.

현재 배포는 GitHub Pages만 사용한다. Netlify는 사용하지 않는다.

## v0.30 두 휴대폰 모션 전투

**첫 연결 순서 (Galaxy Fold6 화면 + Galaxy S21 무기 컨트롤러)**

1. 폴드6에서 https://secom3-tech.github.io/motion-rpg/indoor.html 을 전체 화면으로 연다.
2. 오른쪽 위 '모션 설정' → '연결 코드 만들기'. 화면에 `mrpg-...` 코드가 뜬다.
3. S21에서 https://secom3-tech.github.io/motion-rpg/controller.html 을 열고 코드를 입력하거나 폴드6의 '연결 주소 복사'를 사용한다. '게임 연결'을 누른다.
4. S21에서 '센서 켜기'를 누른다. 투척/검격 모드를 선택하고 필요하다면 민감도와 회전축을 설정한다. 실제 몸 동작이 폴드6 전투의 투척/검격 공격으로 들어간다.
5. 폴드6에서 '카메라 자세 인식 켜기'를 누르고 정면에서 상반신·골반이 보이도록 1.5~2.5m 앞에 선다. 약 2초 가만히 자세 기준을 잡는다. 가로 공격은 앉기, 내려찍기는 좌우 이동으로 회피한다.
6. 모션 설정 창을 닫고 싸운다. 버튼/키보드 회피, 근접 및 원거리 공격은 계속 사용 가능하다.

**현재 기술적 제약**

- GitHub Pages는 정적 호스팅이라 두 기기의 WebRTC 연결을 처음 맺는 데는 무료 PeerJS Cloud 신호 중계 서비스와 외부 PeerJS CDN을 사용한다. 서버 장애, NAT/방화벽, 네트워크 상태에 따라 연결되지 않을 수 있다. GitHub Pages만으로 P2P 연결을 보장하지는 못한다.
- 폴드6 전면 카메라 자세 인식은 MediaPipe Tasks Vision Pose Landmarker Lite 모델(브라우저 내 연산, 약 8 FPS)을 사용하며 모델과 런타임을 CDN에서 다운로드한다. 영상 프레임은 S21로 보내지 않는다. 느린 기기/어두운 곳/프레임 안에 상반신·골반이 보이지 않을 때는 인식이 실패할 수 있다.
- S21은 자세분류 이벤트(검격/투척, 강도, 시각, 시퀀스)만 전송하며 실제 센서 원본 데이터는 폴드6로 전송하지 않는다. 연결 코드는 임시 코드이며 외부와 공유하지 않는다.
- 실제 폴드6·S21의 카메라 권한/센서 권한/통신 지연/장시간 동작은 아직 **실기기 확인 전**이다. 현재는 프로토타입이며 부정행위 차단·안전성·게임 밸런스를 보증하지 않는다.
- 공간을 비우고 기기를 놓치지 않게 잡는다. 스마트폰을 실제로 던지지 않는다. 불편하면 카메라/센서를 끄고 버튼으로 플레이한다.
- 테스트: `node tests/motion.mjs`, `node tests/network.mjs`를 포함한 `npm test`. 기기 2대의 실제 WebRTC 연결 자체는 자동 테스트 대신 현장 점검이 필요하다.

## v0.33 내 무기별 1인칭 전투 연출

- 이전 근접 공격은 무기에 관계없이 같은 CSS 흰색 곡선을 띄운 뒤 즉시 피해를 적용했다. 현재는 실제 장착 무기가 화면 하단에 1인칭으로 보이고, 공격할 때 무기 자체가 움직인다.
- 검: 화면을 가로지르는 휘두르기, 위→아래 내려찍기, 정면 찌르기. 공격 스타일마다 궤적과 피해 가능 각도가 다르다.
- 장검: 푸른색 넓은 검기와 더 느리고 무거운 동작. 도끼: 주황 타격 궤적과 강한 내려찍기. 활: 활몸·시위·화살, 원거리 화살 발사. 지팡이: 고목 지팡이와 파란 정령구 형태의 발사체.
- 물리 충돌: 근접 버튼을 누르는 즉시 피해를 주지 않는다. 타격 동작의 접촉 프레임에 몬스터까지 거리와 방향을 검사한다. 가로베기는 폭이 넓고 찌르기는 좁다. 빗나가면 피해를 주지 않는다.
- 터치: 근접 버튼을 좌우로 드래그하면 가로 베기, 아래로 내리면 내려찍기, 위로 드래그하면 찌르기. 키보드는 F/E/R에 대응한다. 탭은 장착 무기의 기본 공격을 사용한다.
- S21: 원래의 실제 동작 이벤트에 가로/세로/찌르기 구분 정보를 추가했다. 기본 '자동 추정'은 휴대폰 센서축 기반 간이 판정이며 손에 쥔 방향에 따라 틀릴 수 있다. 동작 방향 고정 옵션을 제공한다. 실제 기기 정확도는 확인 전이다.
- 기존 장비 제작·획득 시스템과 연결된 실제 장착 무기가 전투 외형 및 공격 배율을 결정한다. 시착만으로 전투 성능이 바뀌지는 않는다.
- 코드 src/player-combat.mjs, src/weapon-view.mjs, tests/player-combat.mjs. 기존 전투·탐험·재료 정산을 유지한다.

## v0.34 S21 중복 투척과 무기 입력 개선

- 투척은 감지 뒤 최소 1.9초 대기하고, 센서값이 0.75초 이상 낮아져야 다음 동작이 준비된다. 팔 회수 동작을 추가 투척으로 인식하지 않도록 한다.
- S21 컨트롤러의 '자동 전투' 모드는 앞으로 뻗는 동작(추정)을 투척/활 사격, 가로·세로 휘두르기를 근접 공격으로 분류한다. 기존 투척 고정·근접 고정 버튼도 유지한다.
- 공격 방향은 첫 센서값 하나가 아니라 약 150ms의 동작 구간을 모아 분석한다. 3가지 동작(가로·세로·앞으로 뻗기)을 사용자 동작으로 학습해 방향 판정에 사용할 수 있다.
- 자동 분류는 스마트폰의 쥔 방향과 센서축에 따라 틀릴 수 있으며, 구분이 잘되지 않으면 수동 고정 모드를 이용한다. 아직 실기기 정확도 검증 전이다.
- 활의 근접 입력은 강한 검격이 아니라 좁은 사거리의 활 밀치기로 제한하며 검기 형태의 이펙트는 제거했다.
- 버튼 없는 자동 전환은 '실험 기능'이며 실전에서 최적화 완료된 동작 인식이라는 의미는 아니다.

## v0.35 S21 게임패드와 4개 숲 구역

폴드6은 3D 전투·카메라 회피/마을 터치, S21은 전투 조작에 집중한다. 모든 장비·성장·보상은 기존 캐릭터와 공유한다.

- S21에서 이동 가상 조이스틱, 시점 드래그 패드, 락온 켜기/끄기를 사용한다. 기존 센서 켜기, 자동/투척/근접 모드, 민감도, 방향 학습도 유지한다.

- S21 이동 패킷이 약 0.45초 이상 끊기면 폴드6 캐릭터가 자동으로 멈춘다. 화면이 숨겨지거나 연결이 끊겨도 정지하도록 정리했다.
- 맵은 같은 3D 공간 안에 사냥꾼의 숲길, 잊힌 돌 유적, 발광 버섯 습지, 붉은 수풀 공터를 추가했다. 유적 석문·기둥, 버섯·연못, 사냥꾼 야영지를 배치했다.

- 테스트: src/remote-control.mjs, src/forest-encounters.mjs, tests/remote-forest.mjs. 4개 구역 6,000회 몬스터 추출과 입력 만료·중복·락온 방향/공격 영역의 계산 검사.

## v0.37: 숲마을 화면과 실제 사냥에 가까운 전투

- 첫 화면을 사냥꾼 마을로 정리했다. 길드 게시판·대장간·숲 안내인에 직접 말 걸고, 숲 사냥·야외 원정·장비를 선택한다. 배경은 시장 천막, 길드 게시판, 대장간 굴뚝, 주민, 가로등, 숲 입구를 그린 **캔버스 기반 3D풍 마을**이다. 아직 자유 이동형 3D 마을이 아님을 명시한다.
- 오늘의 소문은 매일 바뀌고, 다시 듣기를 누르면 다른 소문을 들을 수 있다. 진행도에 따라 들을 수 있는 소문의 종류가 늘지만 사건의 결말이나 세계관 전체를 미리 노출하지 않는다.
- 사냥 몬스터는 최대 사거리 밖에서 무조건 추격하지 않고 배회한다. 감지 거리 안에 오거나 공격받으면 추격 상태가 되며, 종별로 가로 이동·거리 벌리기·중단·가속·웅크림이 다르다. 늑대/멧돼지의 발 움직임, 슬라임의 점프, 골렘/나무 수호자의 무거운 걸음도 표현한다.
- **자동 락온은 연결 즉시 켜지지 않는다.** S21에서 직접 락온 버튼을 누르고 전방 약 13m 안에 적이 있어야 획득한다. 약 18m 밖으로 멀어지거나 적이 죽으면 락온이 해제된다. 다른 지형 뒤 가림 판정은 아직 없음.
- 경험치는 기본 90XP부터 레벨별 요구량이 늘어난다. 기존 경험치/레벨은 유지하고 구형 저장본이 가진 레벨 진행률까지 고려한다. 실내 사냥/야외 원정/미니게임/훈련에 같은 곡선을 적용한다.
- `src/monster-ai.mjs`, `src/progression.mjs`, `src/town-life.mjs`, `tests/next-phase.mjs` 추가.
- 현재 몬스터는 순차적으로 한 마리씩 나타나며, 진짜 자율 탐색, 보스·드롭·스킬·자유 이동형 마을과 NPC 대화 확장은 이후 작업이다.

## v0.43.4 공격 재입력 대기 HUD (폴드6)

- 주황색 `공격 대기 N초` → 하늘색 `팔을 잠시 멈춰` → 녹색 `공격 가능`으로 표시한다. 센서를 켜지 않았거나 통신이 오래 중단되면 준비 완료로 잘못 표시하지 않는다.

## v0.43.5: S21 시점 회전 민감도 및 Fold6 카메라 확인

- S21 전투 조작 패드 바로 아래 별도 시점 회전 민감도(5단계, 0.5 / 0.75 / 1.0 / 1.4 / 1.9배)를 추가했다. 오른쪽 시점 드래그의 이동량에만 적용하며 공격 동작 인식 민감도·회피 판정을 바꾸지 않는다. S21 로컬 저장소에 설정을 유지한다.
- Fold6 카메라 회피는 이미 통합돼 있었다. 3D 숲 사냥 → 모션 설정 → 카메라 자세 인식 켜기. MediaPipe Lite 모델을 다운로드해 기기 내부 카메라 영상에서 어깨·골반을 분석하고 좌우 회피와 숙이기를 감지해 게임에 전달한다. 실기기에서 카메라 권한 및 인식 정확도를 확인해야 한다.
- 스킬은 현재 S21의 '✦ 스킬 사용' 버튼이나 게임 화면에서만 발동하며 별도 모션 제스처는 아직 없다. 24초 스킬 쿨타임을 사용한다.

## v0.43.6: S21 버튼 유지 + 공격 모션으로 스킬 발동

- S21의 ✦ 스킬 버튼은 단독으로 스킬을 발동하지 않는다. **버튼을 누른 상태에서 검격/투척 동작**이 감지되어야 스킬을 요청한다. 버튼을 놓으면 즉시 일반 공격 모드로 돌아간다.
- 버튼을 누르고 있을 때 색상이 바뀌며, 폴드6은 검의 반월참/활의 정령 관통사격을 현재 장착 무기와 동작에 맞춰 실행한다. 재사용 대기시간은 기존 24초이며, 그동안 스킬을 요청하면 일반 공격으로 바꿔 실행하지 않고 대기 메시지를 준다.
- S21 모션 감지/재무장 쿨타임과 폴드6의 공격 쿨타임은 기존 값을 유지한다. 폴드6 화면 자체에 있는 스킬 버튼은 수동/비모션 조작을 위한 대체 조작으로 유지한다.
- 스킬 준비 플래그는 연결된 S21이 인식한 모션 데이터에만 부착하며 단독 버튼 네트워크 호출은 제거한다. 실기기에서 손가락 누름 유지와 팔 동작을 함께 시험해야 한다.
