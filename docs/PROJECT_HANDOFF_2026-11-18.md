# Motion RPG 개발 인수인계 — 2026-11-18 (v0.48, 집 테스트 기준)

**프로젝트:** https://github.com/secom3-tech/motion-rpg  
**폴드6 게임:** https://secom3-tech.github.io/motion-rpg/preview.html?v=0.48  
**S21 모션 컨트롤러:** https://secom3-tech.github.io/motion-rpg/controller.html?v=0.48

이 문서가 최신 실기기 피드백과 결정의 기준이다. 다른 대화에서 계속할 때 이 파일을 읽고 시작한다. **사용자와 전투 방향을 논의하기 전에 임의로 새로운 기능을 코딩하지 않는다.** 구현이 끝난 내용과 검토 후보를 혼동하지 않는다. 미공개 스토리·비밀·미래 전개는 사용자에게 미리 설명하지 않는다.

## 1. 게임의 본질과 현재 사용 환경

- 본 게임은 **실제 운동을 판타지 RPG 조작으로 사용하는 게임**. 숲 마을 거점, 대장간, 시장, 장비 제작/구입, 아이템 수집, 레벨업, 3D 숲 사냥, 야외 GPS 산책/러닝과 러닝머신을 하나의 브라우저 저장에 연동한다.
- **폴드6(Fold6)** 화면을 거치대에 세워 멀리서 보며 1인칭 WebGL 숲/전투와 전면 카메라 회피 인식에 사용.
- **S21**은 손에 들고 휘두르거나 던지는 듯한 동작으로 공격, 터치 조이스틱으로 이동/시점을 조작. 폴드6과 6자리 숫자 방 코드로 PeerJS/WebRTC 연결. 초보자는 S21에서 "센서 켜기"도 눌러야 한다.
- 몸을 **좌우로 이동하거나 실제로 앉았다 일어나는 회피 운동이 특히 운동 효과가 체감**된다. S21을 들고 팔만 휘두르는 현재 공격은 운동 효과가 불확실하므로 다음 실전 테스트 후 유지 여부 결정.
- 스마트폰을 몇 미터 떨어뜨린 상태라 조그만 화면 글씨는 실전에서 거의 읽을 수 없다. 주요 전투 상태는 큰 글씨/색/음성·소리로 전달한다.
- 사용자 피드백: 실제 S21 인식은 대체로 정확하고 전투 재미는 있으나 회피 판정(과거 18회 중 2회 성공), 스킬 미발동, 작은 글씨, 공격 대기 타이밍, 무기 거리 전환, 자동 생성된 몬스터를 제자리에서만 상대하는 단조로움 개선 요구. 몬스터 기본 공격력·공격 주기는 **올리지 않는다**: 몸으로 싸우는 난도는 충분함.
- 답변은 간결하게 핵심 먼저. 논의 중인 기능은 사전 합의 후 **한꺼번에 수정**, 시험 후 사용자 피드백을 듣는다.

## 2. v0.47까지 구현됨

- 3D 사냥, 시야 자동 락온, 무기 자동 전환, S21 동작 공격/스킬 충전, 카메라 좌우 이동·숙이기 회피 인식.
- v0.47: **"지금 회피!" 안내 구간**에서 감지된 동작은 해당 근접 공격 회피로 예약해 게이지가 끝날 때 보호. 시점도 좌우 기울기 + 플레이어 실제 옆 이동(~1.04 게임 m), 숙이면 카메라 높이 변화. 회피 입력 인식과 성공 판정을 다르게 표시. 발사체 회피 판정 포함.
- 폴드6 카메라 인식 준비에 "가까이/멀리/중앙/준비 완료" 큰 글씨와 음성 도입(어깨 간격 기반 근사; 실제 미터 단위 거리측정 아님). S21 모션과 카메라 모델/전원/인식은 실전에서 점검.
- v0.47 시장 추가: 붕대 **8G / 기력30**, 숲 회복약 **22G / 기력60**, 횃불10G, 지도12G. 자동 회복 옵션 **기본 OFF**, 기력 30% 이하에서 소비품 사용 선택.
- 장비 제작 골드 가격은 초·중·고급 차등 인상(고급 장검 1,400G 등), 몬스터 난이도는 유지. 기존 저장 골드/레벨/장비 보존. 일부 시작 장비에는 페인팅 아트, 추가 장비 및 소모품에는 개선된 SVG 그림.

## 3. v0.48 이번 반영 — 집에 가서 테스트할 버전

**(A) 공격 타이밍 가독성:** S21 모션 준비 상태를 폴드6 화면 중앙 아래 **큰 색상 신호**로 표시. 주황 '공격 대기', 황색/주황 '팔 잠시 멈춰', 초록 '공격!'과 준비 완료 시 짧은 효과음. 시계의 작은 글씨를 쳐다보지 않아도 상태 식별. 기존 근접 센서 쿨타임 **700ms + 정지 350ms**, 원거리 투척 재중복 보호 **1.9초** 및 전투 내부 공격 딜레이는 변경하지 않음. 신호는 S21 연결 시 전투 중 표시.

**(B) 탐색형 사냥:** 한 마리를 죽이면 다음이 **3초 후** 재배치되며, 통상 **19~27 게임 m** 떨어진 숲속에 생성. 기존 자동 등장 거리 11~18m, 1.6초의 초근거리 연속 사냥에서 이동 탐색이 필요한 전투로 변경. 방향/거리 표시는 유지하고 텍스트 강화; 모서리에서는 지도 내 가능한 좌표를 선택. 이 모드는 여전히 S21 조이스틱으로 직접 이동한다. 자동 탐색/자동 이동은 **아직 구현되지 않았다**.

**(C) GPS 산책의 긴 정지 허용:** 강아지가 냄새를 맡느라 오랜 시간 섰다 걷는 반복을 고려. 이전 18초 무갱신이면 신호 끊김 경고 → **정확한 위치 수신 없이 120초 지속 시** 경고. 45m 이상 부정확한 위치는 즉시 거리 기록에 쓰지 않되, **12초 이상** 연속 부정확해야 화면 경고. 짧은 정확도 저하와 정상 복귀, 서 있다 다시 걷는 반복에 음성 연결/재연결을 매번 알리지 않음. 최초 GPS 연결·정말 긴 신호 단절·위치 권한 거부 같은 사건은 음성 안내. 산책 시간/거리 기록은 유효한 위치 이동 감지에 기반하며, 장시간 멈춘 시간은 이동 시간으로 누적되지 않는다. 35초 이상 위치 표본 간격 시 기준점을 다시 잡고 비현실적 이동 점프는 제외한다. 브라우저 절전/통화/백그라운드 제한은 웹앱 차원에서 완전히 방지할 수 없음.

**(D) 이 문서/자동 검증:** `tests/v048-gps-explore.mjs` 포함 `npm test`, GitHub Actions CI와 Pages 상태 확인. 새 릴리즈는 v0.48.

## 4. 사용자 아이디어 — 아령·암밴드형 운동 전투 (검토 중, 아직 구현 금지)

사용자는 **실제 팔 운동이 현재 방식으로 충분한지 집에서 테스트**한 후 결정한다.

- 현재 방식이 재미/운동으로 충분하면 **v0.48의 S21 손에 든 3D 액션 게임을 그대로 발전**시킨다.
- 운동 효과가 낮으면 **양손에 적절한 아령을 들고 S21을 한쪽 팔 암밴드로 부착**하는 운동 중심 모드를 후보로 검토.
- 폴드6 카메라/ S21 센서를 연결하고 숲에 입장한 뒤 **캐릭터가 적을 자동으로 찾고 이동하며 자동 락온/시점 조정**, 플레이어는 손 조작 없이 운동. 적과의 **교전 중에만** 운동 반복을 공격으로 인식.
- 기본 공격은 아령 **휘두르기/던지기가 아니라 통제된 컬(들기→천천히 내리기)** 같은 반복운동. S21 한쪽 팔의 가속도/회전값으로 상향·하향을 상태 전이로 구분해 **한 번의 완전한 반복 동작에 1타**. 강도·지속시간·방향·준비 자세 보정으로 일상적 작은 움직임과 복귀 동작의 이중 인식 방지. 한쪽 암밴드만으로 **다른 손의 동작을 직접 검증할 수 없으므로** 양팔 동기화 검증에는 전면 카메라 팔꿈치/손목 관절 분석 또는 추가 센서가 필요하며 미확정.
- 공격 간격은 현재의 쿨다운으로 단순 제한하는 대신 **완성된 반복 동작 확인 + 최소 센서 디바운스**로 바꿀 수 있다. 현재 쿨타임은 단순 복귀 시 이중 공격 방지뿐 아니라 공격 애니메이션/전투 간격도 담당하므로 무조건 제거하면 오인식 문제가 돌아온다.
- 운동을 연속 수행하면 타격 수/콤보가 늘도록 설계하되 **빠른 반동/과속을 보상하는 방식은 피할 것**. 적 HP/타격당 피해는 완성된 반복 동작 속도에 맞춰 조정할 수 있지만 운동 안전을 우선. 보조 동작은 카메라로 몸 좌우 피하기/앉기, 기존 3D 회피를 이어감.
- 무거운 아령을 들고 급하게 휘두르거나 던지는 식은 부상 위험이 있어 피한다. 실제 사용 시 동선/수평적 움직임/주변 장애물을 고려.
- **이 설계는 미래 후보. 사용자 테스트 피드백과 명확한 승인 없이 개발 시작하지 않는다.**

## 5. S21 연결 관련 현재 답변

- 폴드6 사냥 화면의 모션 설정에서 **"연결 코드 만들기"**를 눌러 임시 **6자리 숫자 방 코드** 생성.
- S21 컨트롤러 페이지에서 그 코드를 입력해 **게임 연결**하고 **센서 켜기**를 눌러야 함.
- 같은 페이지를 켜 둔 채 **재전투**할 때는 연결을 유지한다. 반대로 페이지를 새로 열거나 방이 새로 만들어지면 보통 **새 코드를 다시 입력해야 한다**. 자동 기기 기억·자동 재연결은 아직 구현되지 않았다.
- 새 아령 모드를 채택하면 암밴드 장착 상태에서 숫자 입력이 불편하므로 "기기 기억/재연결"을 설계할 후보이지만 구현 전 인증 안전성/사용자 동의도 고려.

## 6. 다음 대화의 우선순위

1. 사용자가 v0.48 실전 테스트 후 **현재 조작 유지 vs 아령/암밴드 운동 중심 전환** 여부 피드백 제공.
2. GPS 산책 중 멈춤/재출발 반복 시 더 이상 음성 GPS 연결 안내가 반복되는지 확인.
3. 멀리서 '공격 대기' / '팔 잠시 멈춰' / '공격!' 색상과 효과음을 식별할 수 있는지 확인.
4. 처치 후 다음 몬스터까지 **실제로 이동해 찾아가게 되는지** 확인.
5. 카메라 회피 화면 이동·숙이기/회피 성공(입력 인식과 실제 판정 차이), S21 스킬 충전·발동, 골드 시장 구매·회복 자동 사용 등을 다시 확인.
6. 새 운동 모드 채택 때만 자동 길 찾기, 안전한 반복 운동 센서, 콤보/밸런스, 반복 입력 이중 인식 방지, S21 암밴드 연결 UX를 상세 협의.

## 코드 위치

- `preview.html`: 마을 시장/장비/산책 GPS/음성 상태, 진입점.
- `indoor.html`: 3D 사냥, 공격 준비 표시/몬스터 출현/회피 카메라, S21 상태.
- `controller.html`: S21 센서 감지/시점/조이스틱/스킬 충전, 실시간 상태 전송.
- `src/gps-stability.mjs`, `src/gps-feedback.mjs`: GPS 상태·음성·정지 허용.
- `src/combat-spatial.mjs`: 몬스터 출현 거리, 위치/범위 판정.
- `src/dodge-feedback.mjs`, `src/pose-core.mjs`, `src/pose-camera.mjs`: 회피/카메라 관절 인식.
- `src/motion-core.mjs`, `src/player-combat.mjs`: 동작 감지/공격·투척 판정.
- `src/shop.mjs`, `src/gear-game.mjs`, `src/item-art.mjs`: 골드 소비·장비·아이템 아트.
- 테스트: `npm test` (특히 `tests/v048-gps-explore.mjs`).

**주의:** 소스 코드와 자동 테스트만으로 실제 2대 폰 카메라/모션/GPS 결과가 보증되지는 않는다. 현장 테스트 전까지 변경 효과를 과장하지 않는다.
