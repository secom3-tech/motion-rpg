# Motion RPG — 제품 개발 헌장 (2026-11-16)

## 최상위 정의
**게임에서 목표를 이루려고 몸을 움직이다 보니 자연스럽게 운동이 되는 체감형 RPG.**

게임의 목표는 운동 기록/건강 점수 수집이 아니다. 농구와 스쿼시에서 사용자가 즐겼던 것은 기술 향상, 정확성, 공략, 목표 달성이었다. 재미없는 반복 동작에 경험치를 지급하는 운동 보조 앱으로 바뀌지 않도록 한다.

## 세계관과 메인 동선
- **경계의 숲에 자리한 작은 마을이 메인 화면이자 거점**이다. 마을은 훈련장이 아니다.
- 마을 → 숲 탐험(야외 러닝/러닝머신), 실내 전투, 캐릭터/장비/제작으로 들어간다.
- 전투와 탐험의 결과는 같은 캐릭터의 레벨, 장비, 경험치, 재화, 재료와 스킬에 축적된다.
- 방대한 대서사시와 마을 무한 증설보다는 **소규모 세계의 다양한 사건, 몬스터, 희귀 보상, 어려운 도전**을 우선한다.
- 과거 임시로 도입한 '훈련장'이나 '균열 전투'를 별도 세계관이나 게임의 중심으로 오해하지 않는다. 실내 전투도 경계의 숲 모험 세계에 속한다.

## 실내 모드 (3D 모션 액션)
- 폴드6: 거치한 게임 화면 + 카메라의 전신 자세 인식.
- S21: 손에 쥐는 자이로/가속도 센서 기반 검격·투척 컨트롤러.
- 체감 동작: 검을 휘두르기, 마법탄 투척, 몬스터의 공격을 보고 몸을 숙이거나 좌우로 이동해 회피하기.
- 1인칭 화면에는 실제 검과 베기 동작 애니메이션이 나타나야 한다.
- 몬스터 HP, 다양한 공격 패턴, 방어, 반격, 장비, 스킬과 보스전이 필요하다.
- 반복 횟수보다 타이밍, 정확도, 방향과 전략에 의미를 부여한다.
- 기본 웹 3D 숲/슬라임 프로토타입과 폴드6 동작 감지 및 MediaPipe 관절 추적은 개별 실험 성공.
- 그러나 메인 코드의 단순 영상 프레임 차이로는 회피/스쿼트 구분이 어렵다. 관절 추적 기반 자세 판정으로 개선해야 한다.
- S21과 폴드6의 실시간 무선 동작 전송은 아직 확정 검증되지 않았다.

## 실외 모드 (음성 중심 러닝 RPG)
- 공원 도착 후 '탐험 시작'. 이어폰으로 숲·사건·위험·결과를 듣는다.
- GPS로 이동/페이스를 읽고, **실제 페이스 조절로 사건에 대응한다**. 사건마다 폰 화면 버튼을 누르게 하는 것은 원래 목적이 아니다.
- 보통 달리기 → 몬스터 추격(잠깐 가속) → 탈출 → 느리게 회복 → 탐색/보상/새 사건.
- 은신은 속도를 늦추기, 탐험은 페이스 유지 등 다양한 상황을 조합한다.
- 실패도 다음 사건으로 이어진다. 전략·아이템·성향과 다채로운 결과가 필요하다.
- 야외에서는 스마트폰을 허공에 휘두르는 조작을 강요하지 않는다.
- 실내 러닝머신도 같은 캐릭터/음성 모험을 지원하되, 현재 수동 속도 입력은 실제 운동의 증거가 아니다.
- 과속, 급격한 방향전환, 교통 위험 유도 금지. 난이도 상승이 더 빠른 질주 강요가 되어서는 안 된다.
- 현재 음성 러닝 엔진은 원래 구상으로 복귀 중이며, 실제 폴드6 GPS/이어폰/화면 유지 테스트는 아직 진행하지 못했다.

## 사용자가 가장 우려하는 과거 개발 실패
이전 AI RPG에서는 첫 마을만 여러 번 다듬고, 콘텐츠를 차례로 추가하자 후반 지역이 성의 없고 단순해졌다. 초반 설계는 잊히고, 난이도·경제·몬스터·보상 규칙이 흐트러져 쉬운 꼼수로 끝나버렸다.

반드시 지킬 것:
1. 새로운 지역/스토리를 빠르게 늘리기보다 **재조합 가능한 다양한 몬스터/스킬/재료/이벤트** 제작.
2. 쉬워서 바로 깨는 게임보다 플레이 실력과 전략을 요구하는 **도전적인 게임**.
3. 운동 강도는 안전하게 개인 기준으로 조절하되, 게임 난이도는 장비 선택/전투 타이밍/페이스 유지/자원 관리로 만든다.
4. XP, HP, 보상·확률·경제·레벨 규칙은 확정적 엔진으로 계산; AI는 이벤트/대화의 다양화를 담당한다.
5. 새 콘텐츠나 보상 변경마다 1,000회 이상 가상 플레이 검증, 특정 선택지만 정답이 되는 편향/무한 보상/성장 속도/지역 난이도 퇴화를 점검.
6. 자동 검사는 논리 회귀 테스트일 뿐 재미의 증명은 아니다. 최종 판단은 사용자 플레이.
7. 사용자가 게임의 난이도와 보상을 직접 설계해야 한다면 이미 몰입을 해친 것이다. 플레이어에게 밸런스 책임을 전가하지 않는다.
8. 기존 기능과 저장 자료를 파괴하면서 새로운 디자인을 밀어붙이지 않는다. 불확실한 부분은 프로토타입과 확정 기능을 구분한다.

## 지금의 우선순위
- 비로 인해 야외 실전 테스트는 어렵다. **지금은 전체 화면과 게임 흐름이 처음 구상에 맞는지 확인하고, 디테일을 고치는 단계**다.
- 숲마을 메인 → 음성 러닝/러닝머신 → 실내 3D 액션 → 성장·보상으로 이어지는 전체 동선을 사용자가 먼저 평가한다.
- 이후 초기부터 다양한 콘텐츠, 몬스터, 이벤트, 장비와 적절한 난이도를 검증한다.
- 실내/야외 모두 큰 구조를 확정한 뒤에야 센서 인식 정확도와 미세 조작을 다듬는다.

## 캐릭터 외형과 장비 (v0.26)

- 마을의 플레이어 캐릭터는 눈에 보여야 한다. 캐릭터/장비 화면에서는 전신 외형을 크게 확인한다.
- 무기, 머리(투구/후드), 갑옷, 보조장비의 4개 슬롯을 구분한다. 장비가 바뀌면 외형도 즉시 변화한다.
- src/avatar.mjs의 공통 로우폴리풍 캔버스 렌더러를 preview.html의 마을과 장비 화면에서 재사용한다. 실제 스켈레톤 3D 모델은 아니다.
- 시착 조합은 motion-rpg-preview-equipment-v1 키에만 저장하며 실제 인벤토리, 성장, 전투 능력치, 보상에 영향을 주지 않는다.
- 향후 게임 엔진으로 장비 획득/제작/장착 가능 여부를 판정하고 실내 3D 전투에도 같은 장비 외형을 적용한다. 장비를 무한 무료로 지급하지 않는다.
- 기존 저장 데이터, 전투, 탐험 기능을 파괴하지 않고 확장한다.

## 숲마을 확장 v0.27

- 캐릭터의 기본 이미지는 판금 기사보다 사냥꾼/숲 모험가다. 가죽 모자, 천·가죽 방랑복, 활, 여행 가방을 기본 외형으로 설정했다. 중갑 기사는 선택 장비에만 남긴다.
- 길드 의뢰 게시판은 기존 지역 퀘스트/보스 진행 현황을 실제 저장 데이터에서 보여준다. 새 보상은 임의 지급하지 않는다.
- 마을의 대장간은 장비 외형 시착실로, 숲길 안내인은 음성 탐험/러닝머신 입구로 연결된다. 장비 제작 경제 및 NPC 전투 효과는 아직 실장하지 않았다.
- 초기 느낌 확인을 반복적으로 요구하지 않는다. 다음 목표는 전체 게임의 실제 플레이 가능성, 성장과 장비 경제, 전투 입력의 연동이며 변경 시 기존 규칙과 테스트를 유지한다.

## v0.28 전투·제작·실제 장착 루프

- 실내 3D 전투에서 슬라임 3종, 그림자 늑대, 유적 골렘의 특성·반격 예고·회피·기력을 사용한다.
- 전투 결과는 preview.html과 index.html에서 공통 장비/보상 정산 함수를 호출한다. 세션 ID로 중복 수령을 방지한다.
- 전투 경험치/골드와 목재, 수렵 전리품, 정령 조각, 광석을 획득하고 대장간에서 소모해 장비를 제작한다.
- 장비 실제 장착은 기존 공용 캐릭터의 rpgGear 필드에 저장한다. 자유 시착 기능의 저장키와는 완전히 별개다.
- 근접/원거리 공격력, 최대 기력, 피해 감소율에 장착 장비가 영향을 준다. 새 전투 입장에 반영된다.
- 높은 등급 장비는 재료와 골드뿐 아니라 레벨, 숲 지역 보스 격파 조건도 요구한다.
- 야외 GPS 원정의 기존 승인된 보상에만 제작 재료를 연결한다. 데모/러닝머신 수동 입력에 재료 보상을 허용하지 않는다.
- 신체 동작 센서 연동은 아직 검증 전이며, 현재 회피는 버튼과 키보드로 진행한다.
- 정적 웹 저장은 변조 가능하므로 서버 기반 부정행위 방지와 다중 사용자 경제를 완료했다고 주장하지 않는다.

## v0.29 전투 공간 판정

- 몬스터가 언제나 같은 장소에서 출현하지 않는다. 플레이어 현재 위치와 시점을 바탕으로 지도 경계/안전거리를 고려해 여러 위치에 출현한다.
- 공격 판정은 거리 + 몬스터 전방 각도 + 시선 방향을 동시에 충족해야 한다. 플레이어가 몬스터 뒤/옆으로 이동하는 전술이 실제 이득이 되어야 한다.
- 몬스터는 순식간에 회전하지 않고 공격 예고 동안 정면을 고정한다. 플레이어가 경고 중 뒤나 측면으로 피하면 해당 공격은 실패한다.
- 몬스터 외형의 회전은 공격 판정에서 사용하는 실제 방향과 일치해야 한다.
- 피격은 붉은 화면 충격, 흔들림, 피해 수치와 HP UI로 확실하게 전달한다.
- 5종 공격 방향 판정 및 3,000회 안전 위치 출현 자동 검사를 추가했다.

## v0.30 신체 동작을 전투 입력으로 연결

- 폴드6은 3D 게임 화면과 전면 카메라 자세 인식, S21은 6축 IMU를 이용한 검격/투척 컨트롤러 역할을 담당한다.
- 연결은 단일 기기의 브라우저 안에서 완결되는 게 아니므로 WebRTC 연결을 위한 외부 신호 중계 서버가 필요하다. 지금은 GitHub Pages + 공용 PeerJS Cloud를 쓰되 실전 신뢰성은 미확인이다.
- 센서 축 설정, 민감도, 제스처 재준비(히스테리시스), 입력 중복 방지, 통신 시험 기능을 제공한다. 진짜 스마트폰을 던지지 않는다.
- 폴드6 전면 카메라 영상은 폴드6에서만 처리하여 사용자의 좌우 피하기/앉기를 판정한다. 모델 다운로드는 외부 CDN이 필요하며 프레임 자체는 다른 폰으로 보내지 않는다.
- 몬스터 예고 행동은 가로 휘두르기(몸 낮추기)와 내려찍기(좌우 회피)로 갈라진다. 터치 조작은 접근성/모션 실패의 대체 입력으로 남긴다.
- 실제 2기기 연동, 카메라 인식, 장애/끊김 대응, 휴대폰 발열과 배터리 사용은 실전 검증 항목이다. 자동 테스트만으로 성공했다고 주장하지 않는다.

## v0.31 실기기 확인으로 발견한 장애 수정

- 실제 폴드6 화면에서 S21 무선 연결 상태는 성공했지만 실시간 공격은 작동하지 않았고, 카메라 API 모듈 다운로드는 실패했다.
- 연결 성공과 센서 동작 감지를 별도로 보여주고, 수신한 실제 동작이 왜 전투에 적용되지 않았는지를 S21에 응답해야 한다.
- 사용자 친화적인 6자리 연결 코드를 사용하며 구형 코드와도 호환한다.
- 모션 설정 중 전투를 중단해 설명/연결 중 자동으로 기력을 소진하지 않게 하고, 패배해도 통신 연결을 유지한 채 재도전할 수 있어야 한다.
- 카메라 모델/런타임 CDN 문제는 공급 경로 대안을 두되, 실제 모바일 브라우저의 CDN 및 GPU/WASM 동작 테스트가 끝났다고 주장하지 않는다.

## v0.32 적 공격은 반드시 화면에 보여야 한다

- 동작으로 피하는 게임에서는 경고 문구만으로 공격을 설명하지 않는다.
- 공격 준비 자세 → 바닥 위험 범위 → 휘두르기 또는 내려찍기 → 충돌과 회피 판정이 같은 시간축을 따라야 한다.
- 슬라임(몸 압축), 늑대(웅크림과 돌진), 골렘(팔 들어 내리찍기)처럼 종류별로 공격 자세가 달라야 한다.
- 가로 공격은 넓은 전방 부채꼴, 내려찍기는 좁은 전방 부채꼴의 정확한 피해 영역으로 표시한다.
- 공격을 바라보기 어려울 때 보조 문구·색·사운드를 제공하되, 주된 표현은 3D 전투 동작이어야 한다.
- 실제 모바일 WebGL 성능·동작 인식·시야 가림은 실기기에서 검증할 필요가 있다.

## v0.33 플레이어 공격은 무기와 실제 동작에 맞게 보여야 한다

- 몬스터 공격뿐 아니라 플레이어 공격도 화면에서 눈에 보여야 한다. 1인칭 손과 무기는 항상 실제로 장착한 장비와 맞아야 한다.
- 가로 베기와 내려찍기, 찌르기는 서로 다른 손/무기의 이동 경로와 공격 범위를 가져야 한다.
- 검·장검·도끼·활·지팡이의 실물 형태, 손 동작, 근접 타격 잔상, 원거리 발사체를 구분한다.
- 피해는 무기 휘두르기가 도달하는 타이밍과 현재 방향·사거리를 바탕으로 판정해야 한다.
- S21의 실제 방향 감지에는 휴대폰 좌표계에 따른 오차가 있으므로 자동 추정과 명시적인 방향 선택을 함께 제공한다. 실기기 확인 전에는 정확한 자동 방향 인식을 보증하지 않는다.
- 예전 장비 외형 시착과 실제 캐릭터 보유·장착은 서로 다르며, 실전 공격 연출은 실제 장착한 무기를 따른다.

## v0.34 직관적 공격 입력 원칙

- 폰을 앞으로 휘둘렀다가 팔을 되돌리는 전체 사이클은 투척 한 번으로 처리되어야 한다. 단순히 움직임이 여러 번 급해졌다는 이유로 보상을 두 번 주지 않는다.
- 투척은 쿨타임뿐 아니라 낮은 센서값을 유지한 뒤 다시 준비되는 중립화 과정이 필요하다.
- S21에서 근접/원거리를 수동으로 바꿀 수 있고, 자동 전투 모드에서는 움직임 유형으로 구분한다. 자동 분류 결과는 디버그로 확인할 수 있어야 한다.
- 휴대폰을 쥔 자세에 따라 가로·세로 인식축이 달라지므로 전체 동작 구간과 사용자별 동작 학습을 사용한다.
- 활을 장착한 채 근접 입력을 하면 검을 휘두르는 모션이 아니라 활을 이용한 약한 밀치기로 보여야 한다.
- 신규 동작분류는 실기기 결과에 따라 보정하며 과장된 정확도 주장을 하지 않는다.

## v0.35 3D 숲과 실제 몸으로 조작하는 몬스터 전투

- 기존 마을은 폴드6 터치로 운용하고, 전투에서는 폴드6을 화면·회피 감지 장치로, S21을 이동·시점·실제 무기 동작 컨트롤러로 구분한다.
- 락온은 공격/회피 중 시점 조작 부담을 줄이기 위해 쓰며 수동 해제/다른 조작으로 쉽게 변경할 수 있어야 한다.
- 단순히 적의 색상만 바꾸는 대신 외형, 이동 속도, 선호 영역과 공격 패턴을 구별한다. 몬스터별로 준비 동작과 위험 영역이 명확히 보여야 한다.
- 공간은 숲길/유적/습지/공터를 연결한 연속 3D 지도다. 지역별 배경물·적 분포가 달라 탐험의 의미를 준다.
- 다른 액션 RPG와의 가장 큰 차이는 검격·투척과 회피를 사용자의 실제 몸동작으로 수행한다는 점이다. 가상 이동과 시점은 보조 조작이다.
- 외형만 다른 8종이 아니라 돌진, 가로 공격, 내려찍기 등 물리적으로 다른 대응이 필요한 행동들을 점차 확장한다.
- 실제 기기 테스트는 필요하며 모션 안전성·오검출·장시간 플레이 적합성은 아직 보증하지 않는다.

## v0.36 적 탐색은 전투 전에 명료해야 한다

- 숲에서 적이 나타나면 적의 등장 방향과 거리를 알려 사용자가 고개·시점을 돌릴 방향을 알 수 있어야 한다.
- 몬스터의 이름과 체력은 머리 위에 실제 3D 위치를 따라 표시하되, 화면 밖의 몬스터는 위치 표시를 화살표/미니맵으로 대체한다.
- 시점 기준 회전형 미니맵은 플레이어의 현재 방향, 적 위치와 지역 랜드마크를 보여주고 화면 조작을 방해하지 않는 크기를 유지한다.
- 마을은 폴드6 직접 터치, 전투는 S21 제어를 기본으로 하되 적 위치 안내는 폴드6 전투 HUD에서 책임진다.
- 앞으로 단순 순차 소환보다 숲을 탐색해 흔적을 찾고 사냥·전리품·제작으로 이어지는 자연스러운 반복 구조를 우선 개발한다.

## v0.37: 메인 화면과 사냥의 경험 원칙

- 마을을 개발자용 메뉴 화면이 아니라 사람들이 살아가는 거점처럼 보여준다. 시야에 보이는 시설은 소문·의뢰·사냥·장비와 연결한다.
- 소문은 수집/성장과 사냥의 방향을 제시하지만 미래 사건과 전체 이야기의 결말을 사용자에게 미리 보여주지 않는다. 플레이어가 알아내는 게 핵심이다.
- 지역과 생물종마다 고유 이동 방식과 잠복·어슬렁거리기·접근·옆으로 돌기·후퇴 등 행동 변화를 갖는다. 공격 예고 중에는 좌표가 바뀌지 않아 회피 공정성이 유지되어야 한다.
- 적의 위치를 찾아 락온 버튼을 눌러야 조준 보조를 받고, 멀리 있는 적의 방향이 자동으로 따라오지 않아야 한다.
- 레벨업은 점점 많은 경험치를 필요로 한다. 기존 캐릭터의 레벨/경험치/보상 기록을 소급해서 깎지 않는다.
- 야외 달리기에서는 안전을 우선하며 숲 안팎의 소문과 탐색 목표를 공유한다.

## v0.38 게임 UI와 사냥 경험

- HUD나 메뉴를 기술 데모처럼 보이게 만드는 중복 패널을 줄인다. 플레이어는 마을의 중심 화면에서 바로 사냥 또는 야외 원정에 진입한다.
- S21에서는 자주 쓰는 연결/센서/이동/조준/공격 전환과 민감도만 전면에 배치한다. 상세 감도·검격 방향 학습은 고급 설정에 수납한다.
- 굼뜨게 움직이는 몬스터도 비활성처럼 보이지 않도록, 유효 사거리 밖부터 행동하거나 먼 거리에서 예고된 원거리 공격을 수행한다.
- 원거리 공격은 눈에 보이는 발사체를 만들어 이동한다. 즉시 피해나 쫓아오는 유도탄이 아닌 고정 조준으로 이동 회피의 의미를 살린다.
- 플레이 UI는 임시 시뮬레이션 버튼을 숨기며, 테스트·개발 코드 보존 여부는 별도로 관리한다.

## v0.39 마을을 플레이하는 첫 경험

- 마을은 장비/시스템 메뉴가 아니라 플레이어가 이동할 수 있는 공간이다. 주민과 시설 이름을 눌러 이동하고 가까워지면 상호작용한다.
- 마을의 이동은 현재 폴드6 터치·가상 조이스틱으로 처리하며 S21은 전투에 집중한다. 화면을 탭하면 해당 위치 또는 해당 시설로 자동 이동한다.
- 마을은 현재 캔버스 기반 원근 2.5D로, 향후 실제 3D 공간·충돌·NPC 일정·환경 변화를 완성할 기반이다. 개념 이미지의 완전한 3D 품질로 과장하지 않는다.
- 사용자에게는 그 시점에 보이는 마을 소문과 진행 중 목표만 알려준다. 숨겨진 이야기 전개와 미래 이벤트를 미리 공개하지 않는다.
- 이후 3D 숲 사냥과 마을을 같은 장비·보상 저장 상태에 연결하고 이동-전투-보상-복귀의 반복을 강화한다.

## v0.40 그래픽 및 거점 조작 원칙 (2026-11-17 사용자 확정)

- 플레이어는 **마을 안을 걸어 다닐 필요가 없다**. v0.26의 마을 캐릭터 노출, v0.39의 이동형 마을은 당시 시안이었으며, 최신 확정 방향은 **고정된 3D풍 풍경 이미지 + 시설 터치**다. 마을이 살아 있는 거점이라는 세계관은 그대로 유지한다.
- 길드, 대장간, 시장, 숲 진입 지점은 그림 속 인터랙션으로 제공하며 해당 기능 화면을 즉시 연다. 메뉴 여러 겹과 개발자용 시뮬레이션 버튼을 플레이어에게 노출하지 않는다.
- 사냥터와 몬스터는 실시간 3D를 유지한다. 마을은 GPU/WebGL이 아닌 정적 이미지로 가볍게 표현한다.
- 장비 화면도 어설픈 로우폴리 아바타를 확대하는 대신 레이어형 캐릭터 일러스트를 사용한다. 실제 보유·장착·전투력과 자유 외형 시착은 기존처럼 엄격히 구분한다.
- 세계·난이도·경제·보상·숨겨진 스토리는 변경하지 않는다. 본 화면 작업은 게임 플레이의 리소스와 UI를 바꾸는 작업이다.
- 성능은 실제 기기에서 측정해야 하며, 렌더 루프 제거가 FPS 문제를 모두 해결한다고 가정하지 않는다.
