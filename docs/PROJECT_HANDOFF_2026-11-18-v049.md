## 이번 사용자 승인 및 변경 사항

사용자는 기존 게임형 모션 운동 웹앱을 유지하면서, 늑대 공격을 정상화하고 S21 정지 대기를 제거하도록 요청. 아령과 암밴드를 이용하는 별도 운동 버전의 테스트를 명시적으로 승인했다. 스토리/아이템/균형은 임의 공개하거나 변경하지 않는다.

1. `src/monster-ai.mjs`: 늑대는 기존 공격 반경 4.15m 안쪽인 3.25m 유지에 맞추고 과한 궤도 이동을 약간 축소. `indoor.html`: 늑대가 공격 각도를 잠깐 놓쳐도 공격 타이머를 .8초로 반복 초기화하지 않음. 공격 피해/윈드업은 그대로. 실제 공격 빈도는 S21/폴드6 환경에서 검증할 것.
2. `src/motion-core.mjs`: 0.35/0.75초 무조건 정지 조건 제거. 움직임 강도의 상대적 하락을 일정 시간 확인한 뒤 다음 상승 엣지에서 공격 허용. 검격 쿨타임 700ms, 투척 1900ms, 게임 판정 ~620ms 유지. 정지 요구 문구 대신 '동작 마무리'로 변경. 오래 지속되는 강한 흔들림은 여전히 새 공격으로 오인식하지 않음.
3. `src/dumbbell-reps.mjs`, `dumbbell.html`: S21 암밴드에 고정, 중력 벡터의 아래/위 자세를 손으로 2번 기록. 느린 들기 → 맨 위 도달 → 처음 자세까지 완전히 내리기에서 1회로 기록. 1회당 S21 무선으로 '근접 검격' 1번 송신. 한 팔만 감지, 중량·자세 정확도·반대팔 미확인.
4. `indoor.html?mode=dumbbell`: 기존 게임 저장/전투를 쓰되 원거리 탐색 자동 접근(약 2.7게임m/s), 적 자동 방향 추적, 근접 무기 고정. 공격 예고 중 캐릭터의 자동 접근은 멈춤. 회피는 폴드6 카메라/버튼을 그대로 사용. 이 실험 모드는 기존 일반 게임과 별개의 경로이며 일반 모드를 덮어쓰지 않음.

## 퇴근 후 2모드 시험 순서

**일반 모드:** 폴드6에서 일반 게임을 켜고 모션 설정에서 코드 생성 → S21 `controller.html?v=0.49` 에 코드 입력 + 센서 켜기 → 검격을 두 번 연이어 해도 '팔 멈춤'을 요구하지 않는지, 복귀 동작을 중복 공격으로 세지 않는지, 늑대가 접근해 공격하는지 점검.

**아령 모드:** 폴드6 `indoor.html?v=0.49&mode=dumbbell` 에 들어가 모션 설정에서 코드 생성 → S21 `dumbbell.html?v=0.49` 페이지에서 연결 + 센서 켜기 → S21을 암밴드에 단단히 고정한 뒤 아래 자세와 위 자세를 차례로 캘리브레이션 → 팔을 아래로 돌리고 가벼운 컬 5회. 화면의 5회와 폴드6 게임 공격 5번이 대체로 맞는지, 자동 이동과 카메라 회피를 확인.

보정은 S21을 손에 들었을 때가 아니라 **암밴드에 고정된 방향**으로 해야 한다. 실험 중 큰 무게를 들거나 반동으로 공격 횟수를 늘리지 말 것. 스마트폰을 아령 자체에 붙이지 말고 팔에 고정할 것.

## 한계/다음 수정 후보

센서 중력 축 방향은 착용 위치에 따라 달라지고 실물 보정에서 실패할 수 있다. 공격 입력은 브라우저가 활성화되어야 하고 연결은 임시 6자리 WebRTC 코드를 써 재접속 시 다시 생성한다. UI 반복 횟수는 완전한 컬 감지 횟수이지 자세 적합 판정이 아니며, 게임 쿨타임/사거리 때문에 폴드6 공격 인정이 그보다 적을 수 있다. 양손 인식, 기기 기억, 아령 맞춤 균형, 자동 접근 안전성은 아직 현장 검증 전이다. UI 테스트뿐 아니라 실기기 2대 테스트가 필요하다.

기존 v0.48 상태와 스토리 설계는 `docs/PROJECT_HANDOFF_2026-11-18.md`를 유지한다.
